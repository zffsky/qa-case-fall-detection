# QA 实战笔试 — HomeGuard 跌倒检测告警服务

你好，感谢参与这次实战环节。

本仓库包含一个可在本地运行的模拟服务和一份需求文档。我们希望通过它了解你在真实场景下的测试设计、动手能力和取舍判断。

**完成这道题不需要任何硬件、App 或后台账号。** 被测服务就是仓库里的 `app.py`，在你本地运行；真实产品中雷达设备和照护人员 App 发出的请求，都由你通过接口直接模拟。

## 时间

- 请在约定日期前提交 Pull Request。
- 我们预期的实际投入是 **4–6 小时**，请不要超出太多。我们看重的是思路和取舍，不是工作量。

## 关于 AI 工具

**完全允许，也鼓励使用 AI 工具**（Claude、ChatGPT、Copilot、Cursor 等均可）。这正是我们想了解的能力之一。请在交付物中如实记录使用情况。

## 启动服务

需要 Python 3.10 或以上版本。

```bash
pip install -r requirements.txt
python app.py
```

启动后访问 http://127.0.0.1:8000/docs 可以查看接口文档并在浏览器中直接调试。

**环境自检**：访问 http://127.0.0.1:8000/health ，返回 `{"status":"ok"}` 即表示服务正常。

## 任务

阅读 [PRD.md](./PRD.md)，对这个服务进行测试。

建议先读 PRD 第 0、2 节（了解如何在没有硬件的情况下模拟设备和 App），再按第 7 节的完整流程示例操作一遍，熟悉服务行为后再开始设计测试。

## 交付物

请在仓库中新增以下内容：

| 路径 | 内容 |
|---|---|
| `docs/test-design.md` | ① 你认为风险最高的 3 个点及理由；② 假设只有 2 天测试时间，你会测什么、**不测什么**、为什么；③ 核心测试用例 15–20 条（不需要全量）；④ 阅读需求时产生的疑问或你做出的假设 |
| `tests/` | 自动化测试代码。语言和框架不限（推荐 pytest）。要求：一条命令可以执行、可以重复执行且结果稳定、至少包含一个跨多个接口的业务流程场景 |
| `docs/bugs.md` | 你发现的问题，按严重程度排序。每个问题请说明复现步骤、期望结果、实际结果，并指向能复现它的自动化用例 |
| `docs/ai-usage.md` | 简要说明：在哪些环节使用了 AI、贴 2–3 条关键 prompt、AI 的产出你修改了哪些及原因、哪些事情你认为不适合交给 AI |

另外请在 `tests/` 下附一个简短的 README，说明如何运行你的测试。

**请不要修改 `app.py`。** 如果你认为某处是缺陷，请记录在 `bugs.md` 中，而不是去修复它。

## 提交方式

```bash
git clone <本仓库地址>
cd <仓库目录>
git checkout -b submission/<你的名字拼音>

# 完成后
git add .
```

提交过程中可以多次 commit，我们也会看提交记录。
