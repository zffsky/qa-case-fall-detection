# HomeGuard 测试设计

## 风险最高的三个点

1. **跌倒确认与自恢复判定**：漏报可能延误救治，误报会造成照护疲劳。重点在置信度边界、30 秒边界、乱序时间戳、恢复姿态与宠物过滤。
2. **告警生命周期和升级**：告警重复、升级遗漏或无法确认/关闭会直接破坏照护闭环。重点在 120 秒边界、ack 与 resolve 状态转换、同设备告警唯一性和再次跌倒。
3. **照护模式与设备隔离**：照护期间错误告警及设备间状态串扰都可能产生严重后果。重点在切换模式清理疑似状态、模式期间帧处理及多设备并行。

## 两天测试取舍

优先覆盖主业务闭环、判定边界、状态转换、设备隔离、照护模式、异常输入与接口状态码；使用 API 级自动化快速回归，并对时间戳构造边界值。不测真实雷达识别准确率、App/短信/设备鸣响集成、鉴权、压力/性能。

## 疑问与假设

- R9 的 120 秒依据姿态帧时间戳，但实际升级只会在后续帧到达时触发；假设这是预期的模拟方式。
- 被动升级（无新帧时后台计时升级）是否为需求尚不明确；本文按 PRD 的帧 timestamp 模拟方式理解，TC22 暂列为待确认项。
- 若帧时间戳倒退或带时区，产品希望拒绝、忽略还是按设备时间处理？当前需求未定义。
- R8 要求同设备最多一个 open/acknowledged 告警；如果设备处于已有未结束告警时再次确认跌倒，应抑制新告警并保留/清理疑似状态，需求没有说明。
